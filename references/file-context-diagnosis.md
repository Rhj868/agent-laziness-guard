# 场景一：换文件后未按新文件处理

## 现象

上传文件 A 后处理正确，随后上传 B 并发出相同指令，结果仍引用 A、遗漏 B 内容或给出无依据结论。

A 成功只说明当时的处理链路可用，不能证明切换文件时各环节都正确。不得直接归因为「历史记忆污染」或「模型偷懒」。

## 六段排查链路

```
本轮附件识别 → 文件标识传递 → 文件解析 → 检索或内容读取 → 结果生成 → 输出引用
```

逐段确认，定位到**第一个失效环节**后再修复。禁止跳过链路直接修改提示词。

## 五类常见原因

| # | 环节 | 原因 | 验证方式 |
| --- | --- | --- | --- |
| 1 | 附件识别 | 本轮附件未进入处理链路：前端消息未正确传递 B 的文件标识，或 Agent 未调用读取工具 | 查消息负载与工具调用日志，确认是否出现 B 的 ID 和读取动作 |
| 2 | 解析 | 文件解析不完整或失败：格式、加密、扫描图像、表格结构、文件大小都可能影响解析 | 查解析状态、文本长度、必要字段。是否支持 OCR 取决于实际系统能力，不能一概而论 |
| 3 | 检索 | 检索范围或召回不正确：索引尚未完成、过滤条件错误、召回数量不足、阈值不合适 | 查召回片段的 `file_id` 来源是否为 B |
| 4 | 状态 | 工具状态复用了旧值：工具固定读取第一个文件，或 `active_file_id` 未在新上传时更新 | 查任务状态快照与上传事件时间戳 |
| 5 | 上下文 | 多轮上下文造成干扰：历史内容可能让模型偏向旧文件 | 先以日志验证文件读取和检索结果，再判断历史上下文影响；不能仅靠推测认定为记忆污染 |

## 三步快速诊断

1. **对照实验**：在全新会话中仅上传 B，并执行同一指令。
   - 成功 → 比较原会话中的附件标识、工具调用及检索结果，判断历史上下文是否为影响因素。
   - 失败 → 优先排查解析与读取链路，而非会话历史。
2. **日志核对**：日志是否收到 B 的文件 ID；解析文本是否有效且长度合理；检索片段的来源是否为 B。
3. **依据核对**：对关键结论核对原文位置或片段，确认答案确实由 B 支持。

## 五项修复建议

1. **状态管理**：每次新上传时明确更新当前任务的文件 ID；并发任务按任务分别保存状态，不使用可能串线的全局变量。
2. **解析校验**：解析完成后检查状态、内容长度和必要字段。失败时明确报告失败环节，不把失败伪装成「文件没有相关内容」。
3. **检索过滤**：在任务允许范围内按文件 ID 或任务 ID 过滤；校验召回片段来源。用户要求比较多个文件时，明确纳入全部指定文件。
4. **输出依据**：重要结论提供可核对的页码、段落、表格或原文摘录（视系统能力而定）。没有依据时说明「无法确认」。
5. **会话隔离**：业务允许时，将每个文件处理任务放入独立任务上下文；必须多轮比较时，保留用户明确指定的文件集合。

## 文件处理流程规则（六步）

触发条件：用户上传文件并要求分析、修改或提取内容。

1. 获取本轮附件清单及文件标识。
2. 确定本次任务涉及的文件；新上传文件默认作为本轮输入。用户明确要求结合历史文件或比较多个文件时，按要求纳入。
3. 调用文件读取或解析工具，检查工具返回状态、内容是否为空、解析是否明显不完整。
4. 仅依据已成功读取且与任务相关的内容作答；结论尽可能提供可核对的来源位置。
5. 读取失败时说明具体失败环节和可行的重试方式，不编造文件内容。
6. 完成后不把单次文件内容自动写入长期记忆或共享知识库，除非产品设计和用户授权明确要求。

## 不可忽略的判据

- 是否真的读取文件，以**工具调用记录和工具返回结果**验证，不能以模型自述「我已读取」作为证据。
- 提示词只能要求 Agent 遵循上述流程，不能替代读取动作本身。
- 为文件任务记录：本轮文件 ID、解析状态、解析内容长度、检索片段来源。
- 对解析失败、空结果、检索无召回设置明确错误分支，不允许静默走「生成答案」路径。
