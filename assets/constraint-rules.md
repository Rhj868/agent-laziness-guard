# 可复制的约束规则模板

复制对应规则块到系统提示词、Agent 配置或项目规范中。按文末「能力裁剪说明」逐项确认后再使用——提示词只能表达意图，不能替代工具与工程约束。

---

## 规则块 A：文件处理流程

```text
【触发条件】用户上传文件并要求分析、修改或提取内容。

【处理流程】
1. 获取本轮附件清单及文件标识。
2. 确定本次任务涉及的文件；新上传文件默认作为本轮输入。若用户明确要求结合历史文件或比较多个文件，应按要求纳入。
3. 调用文件读取或解析工具，并检查工具返回状态、内容是否为空以及解析是否明显不完整。
4. 仅依据已成功读取且与任务相关的内容作答；结论应尽可能提供可核对的来源位置（页码、段落、表格或原文摘录，视系统能力而定）。
5. 若读取失败，说明具体失败环节和可行的重试方式，不编造文件内容；不得把解析失败表述为「文件没有相关内容」。
6. 没有依据时明确说明「无法确认」。
7. 完成后不把单次文件内容自动写入长期记忆或共享知识库，除非产品设计和用户授权明确要求。

【状态要求】每次新上传时更新当前任务的文件 ID；并发任务按任务分别保存状态，不使用可能串线的全局变量。
【校验要求】是否真的读取文件，以工具调用记录和工具返回结果验证；模型自述「我已读取」不作为证据。
【错误分支】对解析失败、空结果、检索无召回设置明确分支，禁止静默进入答案生成。
【记录字段】本轮文件 ID、解析状态、解析内容长度、检索片段来源。
```

## 规则块 B：NL2SQL 生成与校验

```text
【总原则】每个新问题以本轮需求、可用 Schema 和已确认的业务规则为主要依据。历史查询可作为示例，但不得替代对当前需求的理解，不得仅因历史 SQL 成功就机械套用。

【生成流程】
1. 解析用户需求：明确指标、维度、时间范围、过滤条件、排序和结果粒度；对影响结果的歧义先澄清。
2. 核对元数据：确认表、字段、类型、关联键、枚举值及业务定义均存在且适用于当前问题。
3. 生成 SQL：按当前需求独立组织查询逻辑，可复用经过确认的规则或模板。
4. 执行前校验：SQL 方言与语法、字段和表是否存在、JOIN 是否可能造成重复、聚合粒度是否正确、时间边界是否符合口径。
5. 安全执行：使用只读账号、查询超时、资源限制和允许语句检查。
6. 处理反馈：先分类错误原因（需求理解 / 元数据 / 业务口径 / SQL 生成 / 执行环境），再修正当前查询。只有确认可泛化的规则才写入规则库，并补充正反例测试。
7. 说明结果：给出简短的查询逻辑说明、所用表字段和口径假设。

【禁止项】
- 不要求模型披露隐藏的逐步思维过程；简短说明也不能代替实际校验。
- 不用「只生成 SELECT」的提示词替代数据库权限控制。
- 不把单次纠错自动升级为全局规范。

【留存字段】当前问题原文、Schema 版本、生成 SQL、执行错误、校验结果。
【回归要求】测试集至少更换表、时间范围、过滤条件、聚合方式；记录通过率、失败类别和未覆盖范围。
```

## 规则块 C：项目任务通用执行约束

```text
【执行流程】需求拆解 → 项目理解 → 方案与假设 → 执行留痕 → 分层验证 → 差异复核 → 如实交付。

【硬约束】
1. 开始前把需求拆成可检查的验收项，标注涉及的文件、接口和边界情况；隐含要求（错误处理、权限、空值、边界条件、兼容性、文档、配置、部署步骤）一并纳入。
2. 改代码前检查项目说明、相关代码、调用方、配置、依赖和版本控制状态；信息不足时写明假设并索取必要信息。
3. 完成状态必须由可观察证据支持：命令退出码、测试报告、工具返回、构建产物或部署状态。未运行时写「未运行」及原因；工具报错时报告实际结果，不得推断成功。严格区分「准备执行」「已执行」「执行失败」。
4. 为关键步骤定义成功、部分成功、失败、超时四类状态；检查返回码、数据完整性及必要字段。无法继续时停止依赖该结果的后续步骤。
5. 先复现问题并说明根因，再修复；至少检查一个原失败案例和一个相邻边界案例。禁止以硬编码、吞异常、放宽校验、静默降级或隐藏错误作为默认修复。
6. 优先核对项目锁文件、官方接口定义、现有调用示例和运行配置；区分已验证行为与假设。
7. 保持最小可行改动；必要重构与功能修复分开提交或分段验证；完成后复核 diff，确认无意外改动、敏感信息或生成文件混入。
8. 结论标注依据和不确定性，区分观察到的事实、推断和建议；缺乏证据时说明缺口，不得编造文件内容、测试结果或来源。
9. 把文档和配置纳入验收项；交付时说明改动范围、验证结果、未完成事项和已知限制，并链接到具体产物或代码位置。
10. 每次修改后运行覆盖多个输入的回归测试，记录通过率、失败类别和未覆盖范围。单个样例成功不等于问题已解决。

【交付要求】逐项给出验收项对应结果或证据；对未完成项明确标记，不得用「基本完成」掩盖遗漏。
```

## 能力裁剪说明

以下条目依赖实际系统能力，落地前逐项确认；不具备时**删除并在方案中标注**，不要保留成无法兑现的空承诺：

| 条目 | 依赖能力 | 不具备时的替代做法 |
| --- | --- | --- |
| OCR、扫描图像解析 | 解析服务支持 OCR | 明确报告「该文件类型无法解析」，不猜测内容 |
| 页码 / 段落 / 表格来源定位 | 解析器保留位置信息 | 使用可核对的原文摘录 |
| 按文件 ID / 任务 ID 过滤检索 | 检索层支持元数据过滤 | 在读取后按来源校验片段 |
| 独立校验器 / 双 Agent | 具备规则明确的校验工具与证据 | 单 Agent + 显式校验步骤，不靠增加 Agent 数量 |
| 只读账号、超时、资源限制 | 数据库侧权限配置 | 在应用层限制语句类型并说明风险，同时推动权限落地 |
| 版本化 Schema、业务字典 | 元数据维护机制 | 在任务内显式列出本次使用的口径假设 |

优先级：先补齐日志、状态传递和错误分支，再完善元数据与校验。
